# Worship Broadcast PPT (주일낮 예배 방송실용 PPT/워드 생성기)

## 이 스킬이 하는 일

완성된 설교 원고를 입력받아 두 개의 산출물을 만듭니다:

1. **방송실용 워드(.docx)** — 슬라이드 분할 + 방송 큐(▶ SLIDE, ♬ AUDIO) + 무대 지시 + 색상 가이드가 포함된 마스터 큐시트.
2. **방송실용 PPT(.pptx)** — 위 큐시트와 동일한 슬라이드 구조를 가진 발표용 자료. 각 슬라이드마다 설교 내용에 맞는 시각 디자인이 추천·적용됩니다.

이 두 문서는 단일한 슬라이드 플랜에서 파생되므로 슬라이드 번호·제목·내용이 항상 일치합니다.

## 언제 트리거되어야 하는가

다음 신호가 보이면 즉시 사용:
- "방송실용 PPT", "주일 예배 PPT", "설교 슬라이드", "예배 슬라이드", "방송 큐시트", "예배 진행 워드"
- "이 설교문으로 PPT 만들어줘", "이번 주 설교 자동화"
- 한국어 설교 원고(.docx/.hwp/.txt) 업로드 + "PPT" 또는 "슬라이드" 언급
- 룻기/창세기/시편 등 성경 본문 + 설교 대지 형태의 텍스트 + 슬라이드 산출 요청

일반 PPT 요청은 트리거 대상이 아닙니다 — 이 스킬은 한국 교회 예배 컨벤션이 필수일 때만 사용.

## 핵심 워크플로우 (5단계)

### 1단계: 설교 원고 분석

입력된 원고에서 다음 메타데이터를 먼저 추출합니다:

- **본문 (Scripture)**: 예) "룻기 2:1-14"
- **설교 제목 (Title)**: 예) "긍휼이 머무는 자리"
- **설교자 (Preacher)**: 예) "김동석 목사"
- **예배 종류 (Service Type)**: 기본값 "주일낮 예배" (사용자가 다른 곳을 명시하지 않은 한)
- **예배 일자 (Service Date)**: 사용자에게 묻거나 다음 주일로 가정
- **대지/PART 구조**: 설교 안에 "1.", "2." 같은 번호가 매겨진 섹션이 있는지 확인. 없으면 자연스러운 흐름 단락으로 분할.
- **인용 성경 구절**: 본문 외에 인용된 모든 성경 구절(잠 16:33, 마 11:28 등)을 빠짐없이 목록화.
- **외부 인용**: 본회퍼, 손경민 찬양 같은 외부 자료 식별.
- **추천 결론 찬양**: 설교 결론부에 가사 인용된 찬양이 있으면 그것을 사용. 없으면 설교 주제에 맞는 찬송가/CCM 1곡을 사용자에게 제안하고 동의를 구함.

분석 결과를 사용자에게 요약 보여주고 **승인을 받은 뒤** 다음 단계로 진행. 잘못된 분석으로 32장을 만들면 시간 낭비입니다.

### 2단계: 슬라이드 플랜 작성

`references/slide-types.md`를 읽어 6가지 슬라이드 유형의 정의·포맷·예시를 숙지하세요. 그 후 `references/slide-density.md`를 읽어 설교 길이(약 30분 = 약 32장)에 맞는 분할 가이드를 따르세요.

슬라이드 플랜은 다음 JSON 구조로 작성합니다 (출력은 외부에 보이지 않는 작업용 중간 산출물):

```json
{
  "metadata": {
    "title": "...", "scripture": "...", "preacher": "...",
    "service": "주일낮 예배", "service_date": "...", "total_slides": 32
  },
  "slides": [
    {
      "number": 1,
      "type": "cover | scripture_reading | part_divider | verse_with_message | emphasis | song_lyrics | closing | quotation",
      "title": "표지" | "본문 봉독 · 룻기 2:1 — 3" | "PART 1 · 룻기를 어떻게 읽을 것인가" 등,
      "scripture_block": [ {"ref": "룻 2:1", "text": "..."}, ... ] (해당 시),
      "manuscript_segment": "이 슬라이드 동안 설교자가 말하는 원고 텍스트",
      "key_quote": "강조 문장(있으면, 와인색으로 표시될 부분)",
      "stage_direction": "[ 강대상에 오르심 ]" 같은 무대 지시문 (있으면),
      "audio_cue": "MR 재생 시작 · 「은혜」(손경민)" 같은 ♬ AUDIO 큐 (있으면),
      "visual_design": "시각 디자인 추천 — 배경/레이아웃/이미지 제안"
    }
  ]
}
```

**작성 후 사용자에게 슬라이드 플랜 요약을 보여주고 승인 받기.** 이때 슬라이드 개수, 각 슬라이드 제목 목록, 색상/큐 위치를 한 화면에 정리해서 제시하세요. 사용자가 일부 슬라이드 추가/삭제/병합을 요청하면 반영 후 재승인.

### 3단계: 방송실용 워드(.docx) 생성

`references/broadcast-doc-format.md`를 읽고 형식을 정확히 따릅니다.

이때 반드시 docx 스킬(`/skills/docx/SKILL.md`)을 먼저 읽으세요. python-docx로 워드 문서를 만들 때의 모범 사례가 그 안에 정리되어 있습니다.

문서 머리글은 항상:
```
주일낮 예배  ·  방송실용
[설교 제목]
[본문]    |    [설교자]

[ 방송실 안내 ]
▶  빨강 박스(▶ SLIDE N) 가 보이면 해당 번호의 슬라이드로 전환합니다.
♬  파랑 박스(♬ AUDIO) 가 보이면 해당 음향(MR/효과음) 큐를 진행합니다.
•  설교 본문은 검정색, 성경 구절은 골드색, 강조 문장은 와인색으로 표시되어 있습니다.
•  슬라이드 전환은 큐 표시 직후, 목사님이 해당 본문/내용을 시작하는 시점에 합니다.
```

이후 슬라이드별로 ▶ SLIDE N / 32 헤더 + 슬라이드 제목 + 본문 + 무대 지시문 + 오디오 큐 순서. **색상 적용은 필수**:
- 검정색 (RGB 000000): 설교 본문
- 골드색 (RGB B8860B 권장): 성경 구절
- 와인색 (RGB 722F37 권장): 강조 문장

### 4단계: 방송실용 PPT(.pptx) 생성

이때 반드시 pptx 스킬(`/skills/pptx/SKILL.md`)을 먼저 읽으세요. python-pptx 사용 시의 함정과 모범 사례가 그 안에 있습니다.

각 슬라이드 유형별 레이아웃 가이드는 `references/slide-types.md`에 있습니다. 시각 디자인 추천은 `references/visual-design-patterns.md`를 참조.

**중요 — 시각 디자인은 슬라이드 내용에 맞춰 매번 다르게 추천합니다.** 표준 템플릿을 박제하지 마세요. 예를 들어 "보리밭" 본문 슬라이드에는 황금색 보리 텍스처, "베들레헴 떡집" 슬라이드에는 어두운 빵집 일러스트 분위기, 본회퍼 인용 슬라이드에는 흑백 책 이미지 분위기 등으로 컨텐츠와 시각이 호응하도록.

화면 비율은 16:9 기본. 사용자가 다른 비율을 요청하면 그에 맞춤.

**글자 크기 — 어떤 텍스트도 30pt 미만으로 두지 마세요.**

운평장로교회 본당은 화면과 회중석 사이가 멀어, 작은 글씨는 뒷자리에서 읽히지 않습니다. 슬라이드는 문서가 아니라 **멀리서 보는 표지판**입니다.

| 용도 | 크기 |
|---|---|
| 제목 | 44–60pt |
| 본문·설교 문장 | **36pt 이상** |
| 성경 구절 | **36pt 이상** |
| 출처·각주·절 표기 | **30pt 이상** (이것이 하한선) |

글이 넘쳐서 30pt로도 안 들어가면 **글자를 줄이지 말고 슬라이드를 나누세요.** 한 장에 문장 3–4개면 충분합니다. 폰트를 28pt로 내려 억지로 채우는 것은 잘못된 해결입니다.

만든 뒤 python-pptx로 모든 도형의 `run.font.size` 를 훑어 30pt 미만이 하나라도 있으면 고치고 다시 저장하세요.

### 5단계: 산출물 제시 및 승인

두 파일을 outputs 폴더에 저장하고 computer:// 링크로 제시. 짧은 요약(슬라이드 N장, 인용 성경 구절 M개, 큐 K개) 함께 제공.

사용자가 수정을 요청하면 슬라이드 플랜 단계로 돌아가 부분 재생성. 처음부터 전부 다시 만들지 마세요 — 변경된 슬라이드만 다시 만드는 편이 빠릅니다.

## 절대 지켜야 할 원칙

1. **설교 원문을 변경하지 않는다.** 슬라이드 분할·요약 과정에서 신학적 표현·어휘를 임의로 바꾸지 마세요. 분할은 단락 경계·문장 경계에서만. 요약이 필요하면 사용자에게 명시적으로 동의를 구하세요.

2. **성경 구절 인용은 한 글자도 틀리지 않는다.** 사용자가 명시한 번역본(기본: 개역개정)을 따르고, 인용한 모든 절은 표기와 띄어쓰기까지 정확해야 합니다. 의심스러우면 사용자에게 확인.

3. **승인 게이트를 건너뛰지 않는다.** 1단계 분석 결과, 2단계 슬라이드 플랜 두 곳에서 사용자 승인을 받습니다. 이 게이트를 건너뛰면 32장 만든 뒤 전부 다시 만들 위험이 큽니다.

4. **방송실 큐 컨벤션을 일관되게.** ▶ SLIDE는 슬라이드 전환, ♬ AUDIO는 음향 큐. 두 표시 모두 워드 문서에서 시각적으로 두드러져야 합니다 (대괄호·들여쓰기·색상 등).

5. **PPT의 각 슬라이드는 워드 큐시트의 같은 번호 슬라이드와 정확히 일치해야 한다.** 두 산출물은 동일한 슬라이드 플랜의 두 가지 표현입니다.

## 자주 발생하는 함정

- **너무 많은 슬라이드**: 30분 설교에 50장 이상은 시청자에게 피로. 32장 ± 5장이 적정.
- **본문 봉독 슬라이드에 5절 이상 욱여넣기**: 가독성 저해. 한 슬라이드당 3-5절이 적정. 길면 분할.
- **PART 슬라이드 누락**: 설교 흐름의 큰 전환점에는 반드시 PART 슬라이드를 둬야 청중이 따라갑니다.
- **강조 문장에 색상 미적용**: 와인색 강조는 시각적 리듬의 핵심. 빠뜨리지 마세요.
- **결론부 찬양 가사 슬라이드 누락**: 회중과 함께 부르는 찬양이 있으면 가사 슬라이드는 필수.
