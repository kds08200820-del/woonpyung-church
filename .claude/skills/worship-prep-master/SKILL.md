# Worship Prep Master (예배 준비 마스터 오케스트레이터)

## 이 스킬이 하는 일

설교 원고 한 편을 입력받아, 하위 3개 스킬을 순서대로 호출하여 주일 예배에 필요한 모든 산출물을 한 번에 만듭니다.

**최종 산출물 (한 폴더에 정리)**:
1. `방송실용_워드.docx` — 방송실 큐시트 (worship-broadcast-ppt가 생성)
2. `방송실용_PPT.pptx` — 발표용 슬라이드 (worship-broadcast-ppt가 생성)
3. `기도문_찬송추천.docx` — 대표·중보기도 + 찬송 추천 (worship-prayer-hymn이 생성)
4. `중등부_교재.docx` — 학생용 워크북 (youth-bible-study가 생성)
5. `중등부_교사가이드.docx` — 교사용 가이드 (youth-bible-study가 생성)
6. `worship-context.md` — 모든 산출물의 일관성을 보장하는 공유 컨텍스트

## 언제 트리거되어야 하는가

다음 신호가 보이면 즉시 사용:
- "이번 주 예배 준비 시작", "주일 준비", "예배 준비 자동화"
- "한 번에 다 만들어줘", "설교문 줄게 다 처리해줘"
- "예배 패키지", "주일 자료 일괄"
- 설교 원고 + 여러 산출물 동시 요청 (PPT + 기도문 등)

**단일 산출물 요청 시 트리거되지 말 것**:
- "PPT만 만들어줘" → worship-broadcast-ppt
- "기도문만" → worship-prayer-hymn
- "중등부 교재만" → youth-bible-study

## 핵심 워크플로우 (5단계)

이 워크플로우는 **단계별 사용자 확인**(반자동) 모드입니다. 각 단계 끝에 승인 게이트가 있어, 사용자가 "OK" 해야 다음으로 넘어갑니다.

### 1단계: 설교 분석 + 공유 컨텍스트 생성

`references/worship-context-schema.md`를 읽어 컨텍스트 파일 구조를 숙지하세요.

설교 원고에서 다음을 추출:
- 본문, 제목, 설교자, 예배 일자, 서비스 종류
- 핵심 주제 (1-3 문장)
- 대지/PART 구조
- 인용 성경 구절 모두
- 외부 인용 (저자·책·곡)
- 결론부 권면 또는 결단 메시지

이 정보를 outputs 폴더 안 `worship-context.md`에 저장. 이후 모든 서브 스킬은 이 파일을 단일 출처로 사용.

**사용자에게 분석 결과 요약 제시 → 승인 받기.**
잘못된 분석으로 4개 산출물 다 만들면 시간 낭비입니다.

### 2단계: 작업 범위 확인

사용자에게 어느 서브 스킬을 호출할지 묻습니다. 기본값은 모두 호출.

```
어느 산출물을 만들까요? (복수 선택 가능)
[ ] 방송실용 PPT + 큐시트 워드
[ ] 기도문 + 찬송 추천
[ ] 중등부 성경공부 교재
[모두] 위 3가지 모두
```

선택된 항목만 다음 단계에서 호출.

### 3단계: 서브 스킬 순차 호출

`references/sub-skill-coordination.md`를 읽어 호출 패턴을 숙지하세요.

호출 순서:
1. **worship-broadcast-ppt** (가장 시간이 오래 걸림, 먼저 시작)
   - 입력: 설교 원고 + worship-context.md
   - 출력: 방송실용 PPT + 큐시트 워드
   - 슬라이드 플랜 검토 단계에서 사용자 승인 게이트 (서브 스킬 내부 게이트)
2. **worship-prayer-hymn** (가벼운 작업)
   - 입력: worship-context.md (설교 분석 결과 그대로 활용)
   - 출력: 기도문 + 찬송 추천 워드
   - 사용자에게 어떤 기도/찬송 위치를 원하는지 묻기
3. **youth-bible-study** (중간 복잡도)
   - 입력: worship-context.md + 추가 옵션(시리즈 정보 등)
   - 출력: 학생용 워크북 + 교사용 가이드

각 서브 스킬 호출 후 산출물 미리보기 + 승인 받기 → 다음 서브 스킬로.

### 4단계: 산출물 정리

모든 산출물을 outputs 폴더 아래 단일 폴더에 정리:

```
outputs/주일예배_2026-XX-XX_긍휼이머무는자리/
├── worship-context.md
├── 방송실용_워드.docx
├── 방송실용_PPT.pptx
├── 기도문_찬송추천.docx
├── 중등부_교재.docx
└── 중등부_교사가이드.docx
```

폴더명은 `주일예배_[YYYY-MM-DD]_[설교제목]` 패턴 권장.

### 5단계: 최종 요약 제시

사용자에게 다음 정보 요약:
- 생성된 파일 목록 (computer:// 링크 포함)
- 각 파일 한 줄 요약
- 다음 주일까지 사용자가 검토·수정할 항목 권장 리스트

## 절대 지켜야 할 원칙

1. **공유 컨텍스트가 단일 출처.** 모든 서브 스킬이 같은 worship-context.md를 읽도록. 각 스킬이 독립적으로 설교를 다시 분석하면 결과가 미묘하게 어긋남.

2. **승인 게이트를 건너뛰지 않는다.** 1단계(분석 결과)와 각 서브 스킬 산출물 미리보기 시점에서 사용자 승인을 받음. 사용자가 "전부 한 번에 진행해" 명시하면 게이트 생략 가능.

3. **서브 스킬을 신뢰한다.** 마스터는 호출자일 뿐 컨텐츠 생성자가 아님. 서브 스킬이 작성한 산출물에 마스터가 임의로 손대지 말 것. 수정이 필요하면 해당 서브 스킬을 다시 호출.

4. **부분 실패 시 정리한다.** 3개 서브 스킬 중 1개가 실패하거나 사용자가 거부하면, 나머지 산출물은 그대로 보존. 부분 산출물도 가치가 있음.

5. **폴더 구조를 일관되게.** 주일별로 폴더를 만들어 산출물을 정리. 사용자가 다음 주에도 같은 패턴으로 찾을 수 있게.

## 자주 발생하는 함정

- **컨텍스트 파일 우회**: 서브 스킬에 설교 원고를 그대로 넘기면 같은 분석을 두 번 함. 반드시 worship-context.md 사용.
- **모든 단계를 한 번에 진행**: 사용자가 명시 동의하지 않은 한 단계별 게이트를 지킬 것.
- **시리즈 정보 분실**: 룻기 4주 시리즈처럼 연속 설교라면 worship-context에 시리즈 정보를 넣고 youth-bible-study에 전달.
- **결과물 너무 많은 정보**: 5단계 최종 요약은 핵심 정보만. 학생들이 만든 산출물의 1/10 길이.
