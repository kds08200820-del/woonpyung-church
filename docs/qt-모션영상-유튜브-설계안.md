# QT 모션그래픽 영상 → 유튜브 자동 게시 설계안

2026-11-12 · 담임목사 요청 · 상태: 설계(아직 만든 것 없음)

## 1. 목표

매일 QT 원고에서 모션그래픽 영상을 만들고, 목회행정 매니저에서 확인한 뒤 유튜브에 올리는 것까지 한 줄로 잇는다.
사람이 하는 일은 "확인하고 승인" 한 번이고, 익숙해지면 그것도 생략할 수 있게 한다.

## 2. 참고한 영상과 도구

- 영상: 코드깎는노인 「클로드 오퍼스 5.5, 페이블 5.2로 모션 그래픽 영상 … 무료 스킬 공개」(19분)
- 도구: `script-to-motion` (github.com/kstost/script-to-motion, MIT 라이선스, 무료)

이 도구가 하는 일:

1. 대본을 문장 단위로 나눈다 (`script.txt`).
2. 문장마다 화면(글자·도형·움직임)을 HTML 로 새로 짠다. 그림 AI 를 쓰지 않는다.
3. 화면을 캡처해 겹침·잘림을 스스로 고치고, 별도 '미술 감독' 에이전트가 1~5점으로 채점해 4점이 될 때까지(최대 3회) 고친다.
4. 음성 길이에 화면 길이를 맞춘다.
5. `render.py` 가 한 장씩 그려 MP4 로 굽는다 (기본 1080p 60fps, 세로 9:16 가능, 자막 포함).

알아 둘 점:

- 프로그램이 아니라 **Claude 가 따라 하는 작업 지침(스킬)** 이다. 영상 한 편마다 Claude 가 실제로 일해야 한다.
- 음성은 Fish Audio(유료)만 지원한다. 열쇠가 없으면 무음 영상이 된다.
- macOS·Linux 기준으로 만들어졌다. 교회 PC(Windows)에서 도는지는 아직 확인하지 않았다.
- 굽는 시간이 영상 길이보다 길다.

## 4. 전체 흐름

```
목회행정 매니저 (설교·예배 > 매일 QT)
  └ [영상 제작] → 방식: 모션그래픽 · 화면: 세로/가로 · 게시: 승인 후/자동
        │  video_jobs 에 주문
        ▼
교회 PC 워커
  ① 대본   QT 원고 → 내레이션 대본(60~90초)        ← Claude CLI
  ② 검토 1 대본 확인                                 ← 목사님 (생략 가능)
  ③ 음성   교회 QT 목소리로 녹음, 문장별 길이 재기   ← GPT-SoVITS
  ④ 화면   script-to-motion 으로 장면 제작·자체 채점 ← Claude CLI
  ⑤ 굽기   render.py → MP4 (1080×1920 또는 1920×1080)
  ⑥ 올림   R2 에 저장, 미리보기 주소 기록
  ⑦ 검토 2 영상 확인·수정 요청                       ← 목사님 (생략 가능)
  ⑧ 유튜브 제목·설명·썸네일과 함께 올리기            ← YouTube Data API
  ⑨ 기록   유튜브 주소를 video_jobs 와 그날 QT 글에 적는다
        ▼
홈페이지 QT 글에 영상이 붙고, 매니저에 "유튜브 게시됨" 표시
```

### 단계별 설계

**① 대본** — QT 글을 그대로 읽지 않는다. 본문 한 절 + 묵상 핵심 + 적용 한 가지로 줄인 말하기용 대본을 만든다. 세로 영상은 60~90초(쇼츠는 3분 이하), 가로 영상은 3~5분.

**③ 음성** — script-to-motion 은 Fish Audio 만 알기 때문에, 우리 쪽에서 `audio/narration.wav` 와 문장별 시작·끝 시각을 만들어 넣어 주는 작은 연결 스크립트가 필요하다. 문장을 하나씩 녹음해 이어 붙이면 시각은 정확히 나온다. (도구가 음성 시각을 어떤 파일로 받는지는 0단계에서 확인)

**④ 화면** — 교회 고정 틀을 만든다: 색(흰 바탕·먹색), 글꼴, 첫 장면(날짜·본문 장절), 끝 장면(교회 이름·k-logos.com). 매일 모양이 달라지지 않게 이 틀을 스킬에 지침 파일로 붙인다. 성경 지도·인물 관계·대조 같은 내용은 도형으로 그린다.

**⑧ 유튜브** — 워커가 교회 PC 에 저장된 갱신 열쇠(refresh token)로 올린다. 열쇠는 교회 PC 에만 두고 저장소와 Supabase 에는 넣지 않는다.
- 제목: `[매일 QT] 11월 13일 · 요 3:16 · (QT 제목)`
- 설명: 본문 장절, 묵상 요약 3줄, 홈페이지 주소
- 재생목록 `2026 매일 QT` 에 자동 추가
- 아동용 아님, AI 제작 표시(음성이 합성이므로) 켬
- 예약 공개 시각 지정 가능 (예: 전날 밤 제작 → 다음 날 05:00 공개)

### 화면(목회행정 매니저)에서 바뀌는 것

- 영상 제작 팝업에 `방식`(그림 / 모션그래픽), `유튜브 게시`(안 함 / 승인 후 / 자동), `공개 시각`
- 목록의 상태 표시에 `유튜브 게시됨`·`유튜브 실패` 추가, 누르면 유튜브 주소 열림
- 설정에 유튜브 연결 상태(연결됨 / 다시 로그인 필요), 제목·설명 틀, 재생목록

### DB 변경 (마이그레이션 1개, 추가만)

`video_jobs` 에 칼럼 추가 — 모두 nullable 또는 기본값:

- `engine text default 'illust'` (illust / motion)
- `yt_mode text default 'off'` (off / approve / auto)
- `yt_status text`, `yt_video_id text`, `yt_url text`, `yt_publish_at timestamptz`, `yt_error text`

상태 흐름은 지금 것(pending → processing → review → approved → done)을 그대로 쓰고, 검토 단계에 `publish` 하나만 더한다.

## 5. 먼저 확인해야 하는 위험 (0단계)

1. **유튜브가 API 로 올린 영상을 비공개로 잠근다.** 심사받지 않은 API 프로젝트로 올린 영상은 비공개로 제한된다. 풀려면 구글의 API 심사를 신청해 통과해야 한다(무료, 기간은 몇 주 걸릴 수 있음). 잠긴 영상을 유튜브 스튜디오에서 사람이 공개로 바꿀 수 있는지는 시험 영상 한 편을 올려 봐야 안다. → 통과 전까지는 "비공개로 올라감 → 목사님이 스튜디오에서 공개" 또는 "브라우저로 스튜디오에 올리기" 로 버틴다.
2. **Windows 에서 도구가 도는가.** 굽기(render.py)는 Playwright 라 될 가능성이 높지만 확인 전이다. 안 되면 WSL 로 돌린다.
3. **한 편에 드는 시간과 Claude 사용량.** 장면 제작·채점을 Claude 가 여러 번 하므로 그림 방식보다 사용량이 크다. 매일 한 편이 구독 한도 안에 드는지 실제로 재야 한다. 홈페이지 AI(ai_jobs)·AX 일꾼과 한도를 같이 쓴다.
4. **음성 연결.** 3번 단계의 연결 스크립트가 도구의 구조와 맞는지.
5. **성경 본문 저작권.** 개역개정 본문을 유튜브 화면에 길게 싣는 것은 대한성서공회 허락 범위를 확인해야 한다. 우선 장절 표시 + 한 절 인용으로 짧게 간다.
6. **배경 음악.** 넣는다면 저작권 걱정 없는 곡만(직접 만든 곡 또는 유튜브 오디오 보관함).

## 6. 진행 단계

| 단계 | 하는 일 | 끝난 모습 |
|---|---|---|
| 0. 시험 | 교회 PC 에 도구 설치, 지난 QT 한 편으로 손으로 영상 제작, 시간·사용량 재기, 유튜브에 시험 영상 한 편 올려 잠금 확인 | 영상 1편 + 위험 1~4번 답 |
| 1. 제작 자동화 | 워커에 모션 방식 추가, 교회 틀·음성 연결, 매니저에 방식 선택 | 매니저 버튼 → 검토 화면에 영상 도착 |
| 2. 유튜브 연결 | 구글 클라우드 프로젝트·로그인(목사님이 한 번 동의), 워커에 올리기, DB 칼럼, 매니저 표시 | 승인 누르면 유튜브에 올라가고 주소가 기록됨 |
| 3. 매일 자동 | 전날 밤 자동 주문, 예약 공개, 실패 알림, 홈페이지 QT 글에 영상 붙이기 | 손대지 않아도 아침에 게시 |
| 4. 넓히기 | 주일 설교 요약 영상, 인스타·카카오 채널 동시 게시 | 필요할 때 |

0단계는 DB·홈페이지를 건드리지 않으므로 바로 시작할 수 있다.

## 7. 목사님이 정해 주실 것

1. **영상 모양** — 세로 쇼츠(60~90초) / 가로(3~5분) / 둘 다. 권장: 세로부터.
2. **게시 방식** — 승인 후 게시 / 완전 자동. 권장: 처음 2주는 승인 후, 그다음 자동.
3. **올릴 채널** — 교회 유튜브 채널(어느 구글 계정인지).
4. **목소리** — 지금 QT 목소리(오디오북 낭독자) 그대로 / 다른 목소리. 권장: 그대로.
5. **그림 방식 영상** — 남겨 둘지, 모션그래픽으로 바꿀지. 권장: 남겨 두고 방식 선택.

## 8. 목사님이 직접 하셔야 하는 일 (2단계에서)

- 구글 클라우드에서 유튜브 API 사용 동의 화면에 교회 채널 계정으로 로그인·허용 (한 번)
- API 심사 신청서 제출(내용은 준비해 드림)
- DB 마이그레이션 실행 허락
