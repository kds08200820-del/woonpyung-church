- 들어 있는 것: DB 전체(교적 · 헌금 · 재정 · 게시판 · 설정 …).
- 들어 있지 않은 것: Supabase Storage 의 파일, Cloudflare R2 의 파일(사진 · 영수증 · 음원).

### 되살리는 법

- **연습 · 일부만 꺼내기**: 같은 화면의 「Restore to new project」로 *새 프로젝트*에 되살린다.
  지금 운영 DB 는 그대로이므로 안전하다. 새 프로젝트의 SQL 편집기에서 필요한 줄을 찾아
  운영 DB 로 옮기고(INSERT … SELECT 결과를 손으로 옮기거나 CSV 로), 다 쓰면 새 프로젝트를 지운다.
- **DB 전체를 그 시점으로**: 날짜 옆 「Restore」. 그 뒤에 들어온 자료가 **모두 사라지고** 몇 분 동안 사이트가 멈춘다.
  마지막 수단이다. 누르기 전에 아래 2번의 최신 내려받기가 있는지 먼저 본다.

## 2. 주간 내려받기 — 이 PC 에, 약 두 달치

- 스크립트: `scripts/db-export.mjs` (Docker 필요 없음)
- 만드는 것: `C:\woonpyung-backups\<날짜_시각>\<표>.json` + `_manifest.json`(표마다 줄 수)
- 예약 등록(이 PC 에서 한 번): `powershell -ExecutionPolicy Bypass -File scripts\register-db-export-task.ps1`
  → 매주 주일 새벽 3시, 기록은 `C:\woonpyung-backups\db-export.log`
- 지금 한 번 돌리기: `node scripts/db-export.mjs` (사용자 환경변수 `SUPABASE_SERVICE_ROLE_KEY` 필요)
- **이 파일들에는 교인 개인정보가 있다.** 저장소 · OneDrive · 메신저로 옮기지 않는다
  (스크립트가 저장소 안 · 클라우드 동기화 폴더를 보관 자리로 쓰려 하면 거절한다).
- 되살리기: 필요한 표의 JSON 에서 줄을 골라 SQL 편집기에서 `insert into … select * from json_populate_recordset(null::public.<표>, '<JSON>')`
  로 넣는다. 통째로 덮어쓰지 말고 필요한 줄만.

## 3. 올린 파일(Cloudflare R2 `church-uploads`)

- 지금은 따로 백업이 없다. 지운 파일은 되살릴 수 없다.
- 파일 워커는 본인이 올린 파일만 지울 수 있고, 무인 워커 키로는 지울 수 없다.
- 필요하면 R2 의 「Object lifecycle」 대신 rclone 등으로 다른 저장소에 주 1회 복사하는 것을 검토한다(정해 주실 일).
